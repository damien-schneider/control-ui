  The registry API returns catalog metadata and readable source in a `{ type, data }` envelope. Static shadcn manifests,
  agent metadata, and text indexes expose the same catalog in formats suited to their consumers.

<GuideSection id="endpoints" title="HTTP API">
  List the registry, inspect one item with its dependencies, source files, and anatomy, or search by query. The index links
  the complete skin and theme contracts. An item anatomy slice exposes `ownScopes` for source it owns and `installedScopes`
  for the complete transitive install closure.

  <GuideCode kind="agent-endpoints" />
</GuideSection>

<GuideSection id="mcp" title="MCP server">
  The same catalog is exposed over the Model Context Protocol at `/api/mcp`, streamable HTTP, no authentication. Three
  tools: `search_registry` by keyword, `get_registry_item` for one entry's install command, dependencies, source files
  and anatomy, and `list_registry` for the whole index. Agents that read server cards find it at
  `/.well-known/mcp/server-card.json`.

  <GuideCode kind="agent-mcp" />
</GuideSection>

<GuideSection id="markdown" title="Markdown for agents">
  Every documentation page answers in markdown when the request asks for it, at its canonical URL. Guides return their
  prose and code blocks; component, hook, and skin pages return the install command, dependencies, and installed source
  paths. Browsers keep getting HTML.
