<GuideSection id="pack" title="Start from the defaults">
  “No skin” shows the neutral library baseline. Your application owns its theme and can override only the values
  that need to change. Refined and the other named presets remain optional starting points.

  <GuideCheck>
    Components and portals render without a skin config or provider. Add your brand through application CSS.
  </GuideCheck>
</GuideSection>

<GuideSection id="artifact" title="One artifact owns the theme">
  A theme is one file — `<short-name>.control-ui-theme.json`, format `control-ui-theme/v1` — with tokens split into
  `shared`, `light`, and `dark`. Color-valued tokens go in `light` and `dark`; everything else in `shared`. A token
  left out inherits the base skin, so the artifact composes onto the pack instead of forking it.

  <GuidePoints>
    <GuidePoint>Edit it live in the theme editor, then export the JSON — the toolbar's palette button opens it on any page.</GuidePoint>
    <GuidePoint>Or write it with your agent from a brief: the [theme AI builder](/theme-ai-builder) carries the prompt, the contract, and the import.</GuidePoint>
    <GuidePoint>Each app consumes the artifact as one derived CSS file, imported after the pack's own theme so source order decides.</GuidePoint>
  </GuidePoints>
</GuideSection>

<GuideSection id="contrast" title="Contrast is part of the theme">
  Contrast is a property of the theme, not a follow-up audit. Normal and small text clears 4.5:1 after alpha
  compositing in both modes; focus indicators and control boundaries clear 3:1.

  The [accessibility page](/theme-accessibility) checks the canonical colors plus what the components actually paint —
  popups, badges, active tabs — and the same checks run from the CLI, on every commit, over the baseline and every preset mode.
</GuideSection>
