<GuideSection id="wire-css" title="Wire the CSS">
  Each item adds its own imports to the CSS entry named in `components.json`. Core plus a skin leaves you with:

```css
/* app/globals.css */
@import "tailwindcss";
@import "../components/control-ui/styles/theme.css";

@import "../components/control-ui/styles/skin-theme.css";
@import "../components/control-ui/styles/skin.css";
```

  The registry always writes `../components/…`. When your entry sits elsewhere — `app/globals.css` with `@/*` pointing
  at `./src/*` — run `node <install dir>/scripts/fix-css-imports.mjs`: it rewrites every import to the real path.

  Stamp the pack id on the root element. There is no token fallback when `data-skin` is missing or misspelled:

```tsx
<html data-skin="refined">…</html>
```

  Compiled styles assume Safari 16.4+, Chrome 119+, Firefox 128+; the architecture guide's cascade section derives the
  floor.
</GuideSection>

<GuideSection id="update" title="Update installed components">
  <GuideCode kind="update-install" />

  Updating is a reinstall. The `update` manifest refreshes every installed source and never touches the three
  skin-owned files — a fully custom skin included. Installed source is owned but never edited; customization lives in
  the skin.

  <GuidePoints>
    <GuidePoint>`--diff` previews per-file what the overwrite would change.</GuidePoint>
    <GuidePoint>Installed only a few items? Reinstall those items; `update` pulls the whole set.</GuidePoint>
    <GuidePoint>Refresh a stock skin too: `npx shadcn@latest add …/r/skin-<id>.json --overwrite`.</GuidePoint>
    <GuidePoint>`all-<skin>` with `--overwrite` also updates everything, but resets the three skin files to that pack.</GuidePoint>
    <GuidePoint>After any overwrite: `node <install dir>/scripts/fix-css-imports.mjs` heals the entry imports, and `node <install dir>/scripts/control-ui-doctor.mjs` audits the wiring — imports, theme order, app `@theme` conflicts, `data-skin`.</GuidePoint>
    <GuidePoint>The update also refreshes `.claude/skills/control-ui/SKILL.md`, the agent skill installed with the set.</GuidePoint>
  </GuidePoints>

  Crossing skin contract versions reinstalls core, the affected components or their blocks, and the skin together.
  Version 4 replaced `ToolCall` with Activity's typed tool variant; from version 3 or earlier, remove both old layouts
  before reinstalling:

```bash
rm -f components/control-ui/tool-call.tsx components/control-ui/hooks/use-tool-call.ts
rm -f src/components/control-ui/tool-call.tsx src/components/control-ui/hooks/use-tool-call.ts
```

  Then replace `ToolCall` with `<Activity kind="tool" name="…">` and its `Activity*` parts — `ActivityDetail`,
  `ActivityDetailLabel`, `ActivityDetailContent` — mapping provider status directly to `ActivityState`. Drop
  `useToolCall`; no legacy selectors ship.
</GuideSection>
