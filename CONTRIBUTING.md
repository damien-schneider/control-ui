# Contributing

Thanks for helping improve Control UI. Bug reports, proposals, docs fixes, and new components are all welcome.

## Before you start

- **Bugs:** open an [issue](https://github.com/damien-schneider/control-ui/issues/new/choose) with a reproduction: the component, the skin, what you did, what you expected.
- **New components or API changes:** open a proposal issue first. Say who needs it and in what situation, and sketch the parts and props. Agreeing on the shape before code saves a rewrite.
- **Docs fixes and small bugs:** go straight to a pull request.
- **Security issues:** follow [SECURITY.md](./SECURITY.md) instead of opening an issue.

## Local setup

You need [Bun](https://bun.sh/) at the version pinned in `package.json` (`packageManager`) and Node.js 24.

```bash
git clone https://github.com/damien-schneider/control-ui.git
cd control-ui
bun install
bun run dev
```

The docs app runs at `http://127.0.0.1:3000`. No environment variables are required. Optional ones live in `apps/docs/.env.example`: a registry URL override, the canonical site URL, and search-engine verification tokens. The canonical URL resolves from `NEXT_PUBLIC_SITE_URL`, then Vercel's `VERCEL_PROJECT_PRODUCTION_URL`, then `https://control-ui.dev`, so files generated by a local `bun run sync` carry the production origin.

The docs app tracks preview releases of Next.js and the TypeScript native preview (`typescript@7`). If a check behaves differently on your machine, check your Bun version first.

## How the repository fits together

The docs catalog describes the public product. The registry model derives install targets and dependencies from that catalog and the real import graph. Everything registry-shaped is generated from those two sources:

| Path | What it holds |
| --- | --- |
| `apps/docs/src/registry/sources/control-ui` | Component and kit source (edit here) |
| `apps/docs/src/registry/hooks` and `lib` | Shared component behavior and utilities (edit here) |
| `apps/docs/src/registry/blocks/control-ui` | Installable templates (edit here) |
| `apps/docs/src/registry/skin-packs` | Skin tokens, CSS, typed slots, and adornments (edit here) |
| `apps/docs/app/(features)/catalog` | Product and documentation metadata (edit here) |
| `apps/docs/scripts/registry-model.ts` | Install graph, targets, ownership, and dependencies |
| `apps/docs/registry` | Generated source manifests |
| `apps/docs/src/registry/docs` | Generated per-item markdown, installed beside each component |
| `apps/docs/public/r` | Generated shadcn payloads served to consumers |
| `apps/docs/components/control-ui` | Generated installed copy the docs app renders |
| `packages/components` | `@ctrl-ui/react`; its `src/` is generated |

Never edit generated files. Change the source, then run:

```bash
bun run sync
```

Commit the regenerated outputs with your change. They are marked `linguist-generated` so they stay collapsed in review, and `bun run validate` fails on any drift. `bun run build` regenerates `packages/components/src` from `apps/docs/registry`, so run `bun run sync` first.

Components stay runtime-neutral: installed files never import Mastra, the AI SDK, LangChain, or another model runner. Examples show how to map provider data at the app boundary. The [architecture guide](https://control-ui.dev/architecture) explains the component, runtime, and styling boundaries in depth.

### Previews

Keep docs-only sizing, spacing, and framing out of example source. Declare the frame in the catalog with `preview(loader, { layout })`: `full`, `centered`, `stack`, `grid`, or `contained`. Add `description` to the same options when the main preview needs explaining.

Preview modules start with `"use client"` and load as `import("…").then((mod) => ({ default: mod.ExportName }))`. `bun run sync` turns those loaders into static client references so previews hydrate in place instead of showing a skeleton.

## Commands

| Command | What it does |
| --- | --- |
| `bun run dev` | Docs app plus the fixture sync watcher |
| `bun run sync` | Regenerate manifests, fixtures, public payloads, and agent docs |
| `bun run validate` | Check contracts, catalog data, payloads, and generated drift |
| `bun run typecheck` | Type-check the workspace |
| `bun run lint` | Biome lint, including the class-policy Grit rules |
| `bun run format:check` | Check formatting |
| `cd apps/docs && bun test` | Unit and contract tests |
| `cd apps/docs && bun run test:browser` | Playwright functional suite |
| `cd apps/docs && bun run test:browser:audits` | Performance benchmarks and full-site sweeps, one at a time |
| `bun run build` | Production build of the docs app |

## Pull requests

A pull request must pass:

```bash
bun run validate
bun run typecheck
bun run lint
bun run format:check
cd apps/docs && bun test
```

Also expect to:

- Run the browser tests for anything whose result depends on rendering or interaction.
- Add or update a test when you change behavior. A test has to fail when the behavior breaks; tests that only check wiring get removed.
- Include screenshots, ideally in two skins, for visual changes.
- Name branches `feat/…`, `fix/…`, or `chore/…`, and write commit subjects as `type(scope): change`, for example `fix(tree): keep the focused row visible`.

## Browser tests

Playwright browsers must be installed locally. `bun run test:browser` runs the functional suite on a quarter of your CPU cores against the dev server on port 3000, reusing one that is already running. Tests time out after 60 seconds, actions and assertions after 10. Record a trace for a failure with `--trace on`.

The `audits` project holds the slower checks and runs one test at a time. Run it without other CPU-heavy work, or pass file names to run a subset:

```bash
bun run test:browser:audits e2e/sidebar-performance.pw.ts e2e/tabs-performance.pw.ts
```

| Audit | What it checks |
| --- | --- |
| `*-performance.pw.ts` | Chromium main-thread CPU and style-recalculation time over repeated real pointer and keyboard interactions, against warmed-median budgets |
| `tabs-transition.pw.ts` | Tab slides, height changes, reduced motion, and interrupted transitions |
| `contrast-sweep.pw.ts`, `sidebar-controls-contrast.pw.ts` | Text contrast on every docs page, and on the sidebar controls, across skins and modes |
| `concentric-sweep.pw.ts` | Nested corners follow their surface's curve on every component and kit page |

Tracing and development overlays are off during measurements so recorder work does not count against the budgets.

React Compiler is on in the docs app. Start `NEXT_PUBLIC_REACT_SCAN=1 bun run dev` to inspect rerenders with React Scan. It never loads in production or in automated browsers, so Playwright measures the app alone.

## Code conventions

- No TypeScript `as` assertions except `as const`.
- Colors in `oklch()`; derived colors with relative syntax such as `oklch(from var(--x) l c h / a)`.
- CSS and native platform behavior before React state for interaction, layout, and motion.
- Clear names over comments; delete comments that restate the code.

`AGENTS.md` holds the working rules for coding agents in this repository. The consumer reference lives in `apps/docs/public/llms-full.txt`.
